## 3. TWELVE-STAGE END-TO-END OPERATIONAL WALKTHROUGH

### Stage 1: Interactive Demo Hub & Service Health
- **URL:** `/demo`
- **Action:** Open the Demo Hub. Observe that all 6 services (PostgreSQL, OPA, Docling, BGE-M3, Companion, Web) show green `[ONLINE]` status badges.

### Stage 2: PDF ingestion and Faculty Question Bank

- Upload a synthetic syllabus PDF in the Faculty curriculum workspace. Wait for Docling parsing and the vector indexing job, then request a draft for a covered topic. Verify the draft cites the indexed course material before reviewing it.
- **URL:** Log in as the configured local role account, navigate to `/faculty` -> Question Bank.
- **Action:** Inspect the draft questions generated by LangGraph. Note the explicit citation tags (document ID, page number, section hash) and Bloom cognitive level mapping.
- **Observation:** Notice questions remain in `DRAFT` status until the faculty member clicks `Approve`.

### Stage 3: Blueprint Creation & Bloom Balance
- **URL:** Navigate to `/faculty` -> Exam Blueprints.
- **Action:** Create or review an exam blueprint. Observe the unit distribution (Unit I: 25%, Unit II: 25%, Unit III: 25%, Unit IV: 25%) and Bloom taxonomy balance. Click `Submit to COE`.

### Stage 4: COE Blueprint Ratification (HITL Gate)
- **URL:** Log in as the configured local role account, navigate to `/coe` -> Blueprint Approval.
- **Action:** Review the submitted blueprint. Click `Ratify & Approve Blueprint`.
- **Observation:** Database trigger `trg_assert_blueprint_approved` now permits scheduling.

### Stage 5: Examination Timetable Scheduling
- **URL:** In `/coe` -> Exam Scheduling.
- **Action:** Create a scheduled exam window. Timers are governed strictly by the PostgreSQL server clock, preventing client-side tampering.

### Stage 6: Student Eligibility Verification (OPA)
- **URL:** Log in as the configured local role account, navigate to `/student/dashboard`.
- **Action:** View eligibility status. OPA evaluates attendance (88% >= 75%), fees cleared, and disciplinary standing deterministically via Rego rules.

### Stage 7: Proctor Companion Onboarding & Hardware Check
- **URL:** Navigate to `/student/exam/onboarding`.
- **Action:** Click `Launch Companion`. The companion interface loads on port 4200.
- **Observation:** Web camera captures live face frames; MediaPipe face mesh computes 468 landmarks; audio microphone input registers speech activity.

### Stage 8: Candidate Exam Runner (MCQs & Autosave)
- **URL:** Click `Start Proctored Examination`.
- **Action:** Answer multiple-choice questions. Observe the real-time autosave badge.
- **Security Check:** Note that correct answers are completely absent from the client DOM and network payload.

### Stage 9: Interactive Bubblewrap Coding Runner
- **URL:** Navigate to the Coding section in the Exam Runner.
- **Action:** Select language (Python 3.10), write code, and click `Run Code`.
- **Observation:** Code executes inside an isolated Linux Bubblewrap sandbox (`bwrap --unshare-all`) in **16–25 ms**, returning standard output. Click `Submit Code` to evaluate against secret hidden test cases.

### Stage 10: Invigilator Real-Time Monitoring & Telemetry
- **URL:** Log in as the configured local role account, navigate to `/invigilator/monitoring`.
- **Action:** Observe the active candidate session card, companion heartbeat badge, and incident stream (head yaw, pitch, gaze deviation).
- **Safety Policy:** Non-punitive flags allow invigilators to issue gentle warnings rather than terminating exams.

### Stage 11: Faculty Grading & Subjective Review
- **URL:** Log in as the configured local role account, navigate to `/faculty/grading`.
- **Action:** Review submitted student code and open-ended answers. Objective MCQs are auto-scored deterministically; faculty enters final marks for subjective responses.

### Stage 12: COE Result Publication & Sanitized CSV Export
- **URL:** Log in as the configured local role account, navigate to `/coe/results`.
- **Action:** Review grade distribution and click `Publish Results`.
- **Action:** Click `Download Roster CSV` and `Download Summary CSV`.
- **Security Check:** Open the CSV in a text editor to verify that all cells starting with `=`, `+`, `-`, or `@` are sanitized with a tab character to neutralize CWE-1236 spreadsheet injection.
